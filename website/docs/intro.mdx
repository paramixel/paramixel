# Paramixel

Paramixel turns expensive Java integration tests into **immutable task definitions** that are validated before anything
runs, executed with bounded concurrency, and reported from a single immutable result.

```java
import static org.paramixel.api.Tasks.*;

Task definition = parallel("Environments", Pool.named("environments"))
        .each(environments, environment -> forInstance(environment.name(), () -> new Scenario(environment))
                .before(Scenario::start)
                .sequential("checks", checks -> checks
                        .step("health", Scenario::checkHealth)
                        .step("metrics", Scenario::checkMetrics))
                .after(Scenario::stop))
        .build();

try (Runner runner = Runner.builder()
        .pool(Pool.named("environments"), 3)
        .build()) {
    Result result = runner.run(definition);
    System.exit(result.exitCode());
}
```

## What you get

- **Typed authoring, untyped execution.** `T` is inferred from the instance supplier and carried through nested groups;
  the runtime `Task` is a single immutable type.
- **One definition type.** Steps, groups, instance scopes, conditions, repetition, retries, and timeouts are attributes
  of `Task`, not separate runtime classes.
- **Validation before execution.** Undefined pools, illegal nesting, acquisition cycles, and missing bindings fail before
  any fixture is created.
- **Deterministic scheduling.** Named pools bound concurrency, permits are held for whole subtrees, waiting never occupies
  a worker, and admission is depth-first and deterministic.
- **Honest reporting.** `FAILED`, `SKIPPED`, `ABORTED`, and `CANCELED` are distinct, non-quiescent timeouts are flagged,
  and the same `Result` drives console output and report files.
